CVORCLES v1.0.29 — исправления клиента и сервера

УСТАНОВКА
1. Сделать резервную копию проекта и базы данных. Обновить сервер из server-main_v1.0.29.zip (main.py, requirements.txt и остальные файлы; URL/переменную DATABASE_URL оставить прежними). Render: если корень репозитория содержит main.py, Root Directory пустой; если файлы лежат в папке server, Root Directory = server. Сервер остаётся Python/FastAPI, 1 worker.
2. Открыть project.godot из CVorcles_v1.0.29.zip в прежней версии Godot и экспортировать Android. Версия 1.0.29, код 57. Не менять Android package/подпись: они нужны для сохранения данных на телефоне.
3. Обновить клиент и сервер согласованно. Старый клиент v1.0.28 по-прежнему может отправлять отдельный запрос начисления 1x1; при смешивании версий возможны двойные награды. Новая версия использует /sync_score.

ИЗМЕНЕНИЯ
- 1x1: начисление заработанного рейтинга при серверной фиксации победы; повторный finish_match не меняет рейтинг. Клиент не добавляет его второй раз. Синхронизация при возвращении в лобби.
- Офлайн: начисление фактически заработанного рейтинга за победу над ботом; сохраняется до подтверждения синхронизации.
- 2x2: +70 за победу, существующий штраф -100 при поражении сохранён (до нулевого баланса). Локальная запись завершённых комнат защищает от повторного начисления.
- Локальный рейтинг, ожидающие списания/начисления, инвентарь и купленные сложности сохраняются в одном user://rating_data.json (временный файл + переименование); прежний inventory.json сохраняется для совместимости. Рейтинг старой версии читается. Сервер не хранит инвентарь.
- Покупки, включая сложности ботов и перенос звёзд в стрик, сразу сохраняются на устройстве. Один запрос синхронизации при входе в лобби; при ошибке повторяется каждые 30 секунд в лобби. Идентификатор операции сохраняется до ответа; повторная отправка не удваивает начисление/списание. Без накопленных операций действует max(локальный, серверный). Для новых операций сервер объединяет базовый рейтинг и локальные изменения. На сервере используется одна запись последней операции на игрока в существующей Kv; схема БД прежняя.
- 2x2: нейтральная доступная клетка отличается серой подложкой и серым полупрозрачным слоем поверх рисунка; захваченные клетки сохраняют собственные метки, вражеские — красный оттенок.
- 2x2: боты чередуют захват и способности, выбирают менее предсказуемую цель, имеют индивидуальные задержки 4–7.5 сек после действия; максимум одно действие ботов на общий интервал 1.5 сек. Стартовая пауза больше старой.
- 1x1 и 2x2: добровольный выход или отсутствие активности около 25 секунд (до следующего опроса) передают место боту. Комната не удаляется при выходе, игрок может начать новый матч. Действия ботов выполняются при уже существующих запросах оставшихся игроков, без отдельного фонового игрового цикла. Когда все уходят, комнату удаляет уборщик. В 1x1 состояние замены бота хранится в памяти процесса; перезапуск сервера сбрасывает это временное состояние.
- 2x2: действующее четырёхместное лобби создаёт поле на сервере; старый POST не может заменить его. Неиспользуемые клиентские обработчики удалены. Старый API оставлен для тестовых/совместимых сценариев, в том числе комнаты без полного состава.
- Уборщик: фильтрация просроченных комнат и сирот в SQL, удаление связанных счётчиков кражи, ограниченное число стабильных блокировок, пропуск комнат с активным запросом. HTTP-опрос 1 сек сохранён, чтобы не повышать задержку. Новые авторизация, ограничения и WebSocket не добавлялись. Ресурсы 1x1, скрытая информация, клиентские покупки и старые способности оставлены по указанию.

ПРОВЕРКИ

Проверить на двух телефонах: 1x1 победу, победу над ботом, 2x2 +70, покупку сложности, офлайн-покупку с перезапуском, выход игрока, поведение клеток и скорость ботов. Старые потерянные покупки/рейтинг автоматически не восстанавливаются, если они не были записаны в исходной версии.
